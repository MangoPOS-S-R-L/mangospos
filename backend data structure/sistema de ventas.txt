1.1 DESCRIPCIÓN DEL SISTEMA
================================================================================

MangoPOS es un sistema de punto de venta diseñado para restaurantes que 
permite gestionar ventas tanto en mesa (dine-in) como ventas rápidas 
(takeout/delivery). El sistema está optimizado para pantallas táctiles y 
operación rápida.

CARACTERÍSTICAS PRINCIPALES:
- Gestión visual de mesas por zonas
- Catálogo de productos con personalización
- Carrito de compras con cálculo automático de impuestos
- División de cuentas (manual o equitativa)
- Múltiples métodos de pago
- Envío de comandas a cocina
- Soporte para impresión térmica


================================================================================

================================================================================

El sistema soporta 5 modos de venta:

2.2 TABS DE ZONAS
================================================================================

ZONAS DISPONIBLES:
- Salón Principal (zone: "salon")
- Terraza (zone: "terraza")
- VIP (zone: "vip")

COMPORTAMIENTO DE TABS:
1. Click en tab → Cambia activeZone al valor correspondiente
2. Grid se actualiza mostrando solo mesas de esa zona
3. Contadores se recalculan para la zona seleccionada

CONTADORES:
- "● X disponibles" → Cuenta de mesas con status = "disponible"
- "○ X ocupadas" → Cuenta de mesas con status = "ocupado" o "pagando"

ESTILO DE TABS:
- Tab activo: fondo sólido, texto oscuro
- Tab inactivo: fondo transparente, texto gris
- Transición suave al cambiar

┌─────────────────────────────┐

│─────────────────────────────│

PROPS DE TableCard:
- code: string → Código visual de la mesa (ej: "A1", "T1", "VIP1")
- status: "disponible" | "ocupado" | "pagando"
- guests?: number → Cantidad de comensales (solo si ocupada)
- time?: string → Tiempo desde que se abrió (solo si ocupada)
- total?: number → Total acumulado de la orden (solo si ocupada)
- onClick?: () => void → Handler cuando se hace click

ESTILOS CONDICIONALES:
- Mesa disponible: Borde izquierdo verde (border-l-success)
- Mesa ocupada: Borde izquierdo amarillo/naranja (border-l-warning)
- Hover: Elevación sutil, cursor pointer

================================================================================
2.5 TRANSICIÓN A PANTALLA DE ORDEN
================================================================================

FLUJO AL SELECCIONAR MESA:

1. Usuario hace click en TableCard
2. Se ejecuta handleTableClick(table)
3. Se guarda la mesa en estado selectedTable
4. Renderizado condicional cambia:
   - SI selectedTable !== null → Renderiza OrderScreen
   - SI selectedTable === null → Renderiza TablesGrid

DATOS PASADOS A OrderScreen:
- table: Objeto completo de la mesa seleccionada
- isQuickSale: false (es venta por mesa)
- onBack: Función para volver a TablesGrid (setSelectedTable(null))
- onOrderComplete: Función para completar orden y liberar mesa

3.5 INTERACCIÓN ENTRE COMPONENTES
================================================================================

FLUJO DE DATOS:

     OrderScreen (estado central)
            │
            ├──────────────────────────────────────────┐
            │                                          │
            ▼                                          ▼
      Cart.tsx                                  ProductCatalog.tsx
         │                                          │
         │ solicita:                                │ notifica:
         │ - onSendToKitchen                        │ - onSelectProduct
         │ - onSplitBill                            │
         │ - onPayment                              │
         │ - onUpdateQuantity                       │
         │ - onRemoveItem                           │
         │                                          │
         └──────────────────────────────────────────┘
                            │
                            ▼
                     useCart hook
                   (estado del carrito)


COMUNICACIÓN:

1. Usuario selecciona producto en Catálogo
   → ProductCatalog llama onSelectProduct(product)
   → OrderScreen decide si abrir modal o agregar directo
   → Si modal: abre ProductCustomizationModal
   → Al confirmar: llama addItem del useCart

2. Usuario modifica cantidad en Carrito
   → Cart llama onUpdateQuantity(itemId, newQty)
   → OrderScreen llama updateItemQuantity del useCart
   → Carrito se re-renderiza con nueva cantidad

3. Usuario presiona "Pagar"
   → Cart llama onPayment()
   → OrderScreen abre PaymentModal
   → Al confirmar pago: cierra orden y mesa

4.2 SISTEMA DE BÚSQUEDA
================================================================================

INPUT DE BÚSQUEDA:
- Placeholder: "Buscar productos..."
- Icono: Search (lucide-react) a la izquierda
- Botón X para limpiar (visible cuando hay texto)
- Debounce: 300ms antes de filtrar (evitar renders excesivos)

COMPORTAMIENTO:
1. Usuario escribe en input
2. Se filtra la lista de productos en tiempo real
3. Filtro aplica a: nombre del producto (case insensitive)
4. Si hay categoría seleccionada: filtra dentro de esa categoría
5. Si no hay categoría: filtra todos los productos

EJEMPLO:
- Input: "poll"
- Resultado: Muestra "Pollo Frito", "Pollo a la Plancha", etc.

4.4 TABS DEL CATÁLOGO
================================================================================

TAB "CATEGORÍAS":
- Valor: "categorias"
- Comportamiento:
  - Si selectedCategory = null → Muestra grid de categorías
  - Si selectedCategory != null → Muestra productos de esa categoría

TAB "MENÚ":
- Valor: "menu"
- Comportamiento:
  - Siempre muestra todos los productos
  - Ignora selectedCategory
  - Útil para búsqueda global

TAB "FAVORITOS":
- Valor: "favoritos"

================================================================================
5.7 VALIDACIONES
================================================================================

ANTES DE PERMITIR "AGREGAR AL PEDIDO":

1. VALIDAR CANTIDAD:
   - quantity >= 1 ✓

2. VALIDAR GRUPOS REQUERIDOS:
   Para cada grupo donde required === true:
   - Verificar que selectedModifiers incluye al menos una opción del grupo
   - Si falta: marcar grupo con error, deshabilitar botón

3. VALIDAR MIN SELECTION:
   Para cada grupo:
   - Contar cuántos modificadores del grupo están seleccionados
   - Si count < minSelection: error

4. VALIDAR MAX SELECTION:
   Para cada grupo:
   - Contar cuántos modificadores del grupo están seleccionados
   - Si count > maxSelection: error (no debería pasar si UI lo previene)

FUNCIÓN isValid:
```typescript
const isValid = useMemo(() => {
  if (!product?.modifierGroups) return true;
  
  return product.modifierGroups.every(group => {
    if (!group.required) return true;
    
    const selectedCount = selectedModifiers.filter(
      m => m.groupId === group.id
    ).length;
    
    return selectedCount >= (group.minSelection || 1);
  });
}, [product, selectedModifiers]);
```

MODO A: DIVISIÓN MANUAL
- El usuario asigna cada item a una subcuenta específica
- Cada subcuenta puede tener diferentes items y montos
- Útil cuando cada persona paga exactamente lo que consumió

MODO B: DIVISIÓN EQUITATIVA
- El total se divide entre un número de personas
- Cada subcuenta tiene el mismo monto
- Útil para dividir la cuenta "a la mitad" o entre varios

9.4 FLUJO DE PAGO EN EFECTIVO
================================================================================

PASO 1: Seleccionar método "Efectivo"
- Tab "Efectivo" se activa
- Numpad se hace visible
- Input de monto se habilita

PASO 2: Ingresar monto recibido

   OPCIÓN A - Botones rápidos:
   - [Exacto]: amountReceived = total
   - [+100]: amountReceived += 100
   - [+500]: amountReceived += 500
   - [+1000]: amountReceived += 1000

   OPCIÓN B - Numpad:
   - Dígitos 0-9: Concatenan al monto
   - [⌫] (Backspace): Elimina último dígito
   - [C] (Clear): Resetea a 0
   - [00]: Agrega dos ceros
   - [.]: Agrega punto decimal

PASO 3: Verificar cambio
- change = amountReceived - total
- Si change >= 0: Mostrar cambio en verde
- Si change < 0: Mostrar "Monto insuficiente" en rojo

PASO 4: Confirmar
- Botón "Confirmar Pago" enabled solo si change >= 0
- Click → Procesa pago

CÁLCULO DE CAMBIO:
```typescript
const change = amountReceived - total;
// change >= 0: válido
// change < 0: inválido
```

   - Cierra modal de pago
   - Muestra toast: "Pago procesado correctamente"
   - Si hay cambio: "Cambio: RD$ X"
   - Llama onOrderComplete()

2. BACKEND:
   - Crear registro en payments
   - Actualizar order.status_ext = 'paid'
   - Actualizar order.closed_at = now()
   - Cerrar table_session.closed_at = now()
   - Actualizar dining_table.state = 'available'
   - Registrar en cash_transactions (si efectivo)
   - Generar fiscal_document (NCF) si aplica
   - Crear print_job para recibo

3. POST-PAGO:
   - Mesa vuelve a estado "disponible"
   - OrderScreen se cierra
   - Vuelve a TablesGrid

// src/types/pos.ts

PRODUCT
-------
interface Product {
  id: string;                      // UUID único
  name: string;                    // Nombre visible
  price: number;                   // Precio base en centavos o unidades
  image?: string;                  // URL de imagen
  categoryId: string;              // FK a categoría
  hasModifiers: boolean;           // Si tiene opciones de personalización
  modifierGroups?: ModifierGroup[]; // Grupos de modificadores
}

MODIFIER_GROUP
--------------
interface ModifierGroup {
  id: string;                      // UUID único
  name: string;                    // Ej: "Término de cocción"
  required: boolean;               // Si es obligatorio seleccionar
  minSelection: number;            // Mínimo de opciones (0 si opcional)
  maxSelection: number;            // Máximo de opciones (1 = radio)
  modifiers: Modifier[];           // Lista de opciones
}

MODIFIER
--------
interface Modifier {
  id: string;                      // UUID único
  name: string;                    // Ej: "Término medio"
  price: number;                   // Precio adicional (0 si no aplica)
}

SELECTED_MODIFIER
-----------------
interface SelectedModifier {
  groupId: string;                 // ID del grupo al que pertenece
  groupName: string;               // Nombre del grupo (para display)
  modifierId: string;              // ID del modificador seleccionado
  modifierName: string;            // Nombre del modificador
  price: number;                   // Precio adicional
}

CART_ITEM
---------
interface CartItem {
  id: string;                      // ID único del item en carrito
  productId: string;               // FK al producto
  product: Product;                // Objeto producto completo
  quantity: number;                // Cantidad
  selectedModifiers: SelectedModifier[]; // Modificadores elegidos
  notes: string;                   // Notas del cliente
  unitPrice: number;               // Precio unitario (base + mods)
  totalPrice: number;              // unitPrice × quantity
}

TABLE
-----
interface Table {
  id: string;                      // UUID único
  code: string;                    // Código visual (ej: "A1")
  status: "disponible" | "ocupado" | "pagando";
  guests?: number;                 // Comensales (si ocupada)
  time?: string;                   // Tiempo transcurrido
  total?: number;                  // Total acumulado
  zone: string;                    // Zona: "salon", "terraza", "vip"
  orderId?: string;                // ID de orden activa (si aplica)
}

SUB_ACCOUNT
-----------
interface SubAccount {
  id: string;                      // UUID único
  name: string;                    // Nombre de la subcuenta
  items: CartItem[];               // Items asignados
  subtotal: number;                // Suma de items
  tax: number;                     // ITBIS
  total: number;                   // subtotal + tax
  paid: boolean;                   // Si ya fue pagada
}

================================================================================
12.1 useCart - GESTIÓN DEL CARRITO
================================================================================

UBICACIÓN: src/hooks/use-cart.ts

ESTADO INTERNO:
```typescript
const [items, setItems] = useState<CartItem[]>([]);
```

FUNCIONES EXPUESTAS:

addItem(product, quantity, modifiers, notes)
--------------------------------------------
Agrega un nuevo item al carrito.

Parámetros:
- product: Product - El producto a agregar
- quantity: number - Cantidad
- modifiers: SelectedModifier[] - Modificadores seleccionados
- notes: string - Notas del cliente

Lógica:
1. Calcular modifiersTotal = SUM(modifiers.price)
2. Calcular unitPrice = product.price + modifiersTotal
3. Calcular totalPrice = unitPrice × quantity
4. Generar ID único para el item
5. Crear objeto CartItem
6. Agregar al array de items

NO AGRUPA items iguales - cada agregado es un item nuevo.

updateItemQuantity(itemId, quantity)
------------------------------------
Actualiza la cantidad de un item existente.

Lógica:
- Si quantity <= 0: Eliminar item (llama removeItem internamente)
- Si quantity > 0: Actualizar quantity y recalcular totalPrice

removeItem(itemId)
------------------
Elimina un item del carrito.

Lógica:
- Filtrar items para excluir el del ID dado

clearCart()
-----------
Vacía completamente el carrito.

Lógica:
- setItems([])

VALORES CALCULADOS (useMemo):

subtotal
--------
Suma de todos los totalPrice de items.
```typescript
const subtotal = useMemo(() => {
  return items.reduce((sum, item) => sum + item.totalPrice, 0);
}, [items]);
```

tax
---
ITBIS calculado sobre el subtotal.
```typescript
const tax = useMemo(() => {
  return Math.round(subtotal * TAX_RATE);
}, [subtotal]);
```

total
-----
Subtotal más impuesto.
```typescript
const total = useMemo(() => {
  return subtotal + tax;
}, [subtotal, tax]);
```

itemCount
---------
Suma de todas las cantidades.
```typescript
const itemCount = useMemo(() => {
  return items.reduce((sum, item) => sum + item.quantity, 0);
}, [items]);
```

RETURN:
```typescript
return {
  items,
  addItem,
  updateItemQuantity,
  removeItem,
  clearCart,
  subtotal,
  tax,
  total,
  itemCount,
  setItems, // Expuesto para casos especiales (ej: cargar orden existente)
};
```

================================================================================
13.1 REGLAS DEL CARRITO
================================================================================

REGLA: CANTIDAD MÍNIMA
- Todo item debe tener quantity >= 1
- Si quantity llega a 0, el item se elimina automáticamente

REGLA: NO AGRUPACIÓN
- Items idénticos NO se agrupan
- Cada agregado crea un nuevo CartItem con ID único
- Razón: Permite notas/modificadores diferentes para "el mismo" producto

REGLA: RECÁLCULO AUTOMÁTICO
- Al cambiar quantity → Recalcular totalPrice
- Al modificar items → Recalcular subtotal, tax, total

REGLA: PERSISTENCIA
- El carrito vive en memoria durante la sesión
- Al recargar página → Se pierde (a menos que se implemente persistencia)
- Para mesas ocupadas → Cargar orden existente del backend


================================================================================
13.2 REGLAS DE MODIFICADORES
================================================================================

REGLA: GRUPOS REQUERIDOS
- Si modifierGroup.required === true
- Usuario DEBE seleccionar al menos minSelection opciones
- No puede agregar al carrito sin cumplir esto

REGLA: SELECCIÓN ÚNICA (RADIO)
- Si maxSelection === 1
- Solo una opción puede estar seleccionada
- Nueva selección reemplaza la anterior

REGLA: SELECCIÓN MÚLTIPLE (CHECKBOX)
- Si maxSelection > 1
- Puede seleccionar hasta maxSelection opciones
- Al llegar al máximo, no permite seleccionar más

REGLA: PRECIO ADICIONAL
- Precio del modificador se suma al precio base
- modifier.price puede ser 0 (opción sin costo extra)
- Precio negativo: descuento (poco común)


================================================================================
13.3 REGLAS DE PAGO
================================================================================

REGLA: MONTO MÍNIMO EFECTIVO
- Para pago en efectivo: amountReceived >= total
- Si amountReceived < total → No permite confirmar

REGLA: COBRO EXACTO
- Para tarjeta y transferencia: amountReceived = total
- No hay cálculo de cambio

REGLA: REFERENCIA OPCIONAL
- Para tarjeta/transferencia: referencia es opcional
- Se guarda si se proporciona

REGLA: CAMBIO
- change = amountReceived - total
- Solo aplica para efectivo
- Se muestra al usuario
- Se registra en payment.change_amount

REGLA: CIERRE DE MESA
- Al confirmar pago → Mesa cambia a "disponible"
- table_session.closed_at = now()
- dining_table.state = 'available'


================================================================================
13.4 REGLAS DE MESA
================================================================================

REGLA: UNA SESIÓN ACTIVA
- Una mesa solo puede tener una table_session abierta
- Al abrir nueva sesión → Verificar que no haya activa

REGLA: ESTADOS VÁLIDOS
- disponible: Puede iniciar nueva orden
- ocupado: Tiene orden activa
- pagando: En proceso de cierre

REGLA: TRANSICIONES PERMITIDAS
- disponible → ocupado (al agregar items)
- ocupado → pagando (al iniciar pago)
- pagando → disponible (al completar pago)
- ocupado → disponible (al cancelar orden)
- NO: disponible → pagando (no tiene sentido)

REGLA: VISUALIZACIÓN
- Mostrar comensales solo si hay dato
- Mostrar tiempo solo si ocupada
- Mostrar total solo si hay items


================================================================================
13.5 REGLAS FISCALES
================================================================================

REGLA: ITBIS
- Tasa fija: 18%
- Se aplica sobre el subtotal
- Redondeo: Math.round() al peso más cercano

REGLA: NCF (PENDIENTE IMPLEMENTACIÓN)
- Generar al momento del pago
- Tipo según cliente (B01, B02, B15, etc.)
- Validar secuencia disponible

REGLA: DOCUMENTO FISCAL
- Crear registro en fiscal_documents
- Asociar a orden y pago
- Incluir desglose de impuestos

```sql
INSERT INTO table_sessions (
  table_id, opened_by, customer_name, people_count, origin

```

AL AGREGAR ITEM A ORDEN:
```sql
INSERT INTO order_items (
  order_id, product_id, product_name, qty, unit_price, subtotal, notes, status
) VALUES (?, ?, ?, ?, ?, ?, ?, 'draft')
RETURNING id;

-- Para cada modificador
INSERT INTO order_item_modifiers (item_id, name, qty, price)
VALUES (?, ?, 1, ?);
```

AL ENVIAR A COCINA:
```sql
UPDATE orders SET status_ext = 'sent' WHERE id = ?;
UPDATE order_items SET status = 'queued' WHERE order_id = ?;
```

AL DIVIDIR CUENTA:
```sql
-- Crear check por subcuenta
INSERT INTO order_checks (order_id, label, position, subtotal, tax, total)
VALUES (?, ?, ?, ?, ?, ?)
RETURNING id;

-- Asignar items al check
UPDATE order_items SET check_id = ? WHERE id = ANY(?);
```

AL PROCESAR PAGO:
```sql
-- Crear pago
INSERT INTO payments (
  business_id, order_id, check_id, payment_method_id, 
  amount, reference, change_amount, status, processed_by, session_id
) VALUES (?, ?, ?, ?, ?, ?, ?, 'completed', auth.uid(), ?)
RETURNING id;

-- Cerrar orden
UPDATE orders SET status_ext = 'paid', closed_at = now() WHERE id = ?;

-- Cerrar sesión
UPDATE table_sessions SET closed_at = now() WHERE id = ?;

-- Liberar mesa
UPDATE dining_tables SET state = 'available' WHERE id = ?;

-- Registrar en caja (si efectivo)
INSERT INTO cash_transactions (session_id, amount, type, related_order_id)
VALUES (?, ?, 'sale', ?);
```

15.3 FUNCIONES HELPER PARA RLS
================================================================================

-- Función: Verificar acceso a negocio
CREATE OR REPLACE FUNCTION user_has_business_access(business_uuid UUID)
RETURNS BOOLEAN AS $$
  SELECT EXISTS (
    SELECT 1 FROM users
    WHERE id = auth.uid()
    AND business_id = business_uuid
    AND is_active = true
  );
$$ LANGUAGE sql SECURITY DEFINER STABLE;

-- Función: Obtener rol del usuario en negocio
CREATE OR REPLACE FUNCTION user_business_role(business_uuid UUID)
RETURNS TEXT AS $$
  SELECT role FROM users
  WHERE id = auth.uid()
  AND business_id = business_uuid
  LIMIT 1;
$$ LANGUAGE sql SECURITY DEFINER STABLE;

-- Función: Generar siguiente NCF
CREATE OR REPLACE FUNCTION generate_next_ncf(
  p_business_id UUID,
  p_branch_id UUID,
  p_ncf_type TEXT
)
RETURNS TEXT AS $$
DECLARE
  v_sequence ncf_sequences%ROWTYPE;
  v_next_number INTEGER;
  v_ncf TEXT;
BEGIN
  SELECT * INTO v_sequence
  FROM ncf_sequences
  WHERE business_id = p_business_id
    AND branch_id = p_branch_id
    AND ncf_type = p_ncf_type
    AND is_active = true
    AND (expiry_date IS NULL OR expiry_date >= CURRENT_DATE)
  FOR UPDATE;

  IF NOT FOUND THEN
    RAISE EXCEPTION 'No hay secuencia NCF disponible para tipo %', p_ncf_type;
  END IF;

  v_next_number := v_sequence.current_sequence + 1;

  IF v_next_number > v_sequence.range_end THEN
    RAISE EXCEPTION 'Secuencia NCF agotada para tipo %', p_ncf_type;
  END IF;

  UPDATE ncf_sequences
  SET current_sequence = v_next_number
  WHERE id = v_sequence.id;

  v_ncf := v_sequence.prefix || LPAD(v_next_number::TEXT, 8, '0');

  RETURN v_ncf;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

ON orders FOR SELECT
USING (user_has_business_access(business_id));

ON orders FOR INSERT
WITH CHECK (user_has_business_access(business_id));

ON orders FOR UPDATE
USING (user_has_business_access(business_id));
