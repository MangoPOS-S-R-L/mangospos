// Estado de las mesas
const [tables, setTables] = useState<Table[]>(initialTables);
const [selectedTable, setSelectedTable] = useState<Table | null>(null);

// Al seleccionar mesa → abre OrderScreen
const handleTableClick = (table: Table) => {
  setSelectedTable(table);
};

// Al completar orden → libera la mesa
const handleOrderComplete = (tableId?: string) => {
  if (tableId) {
    setTables((prev) =>
      prev.map((t) =>
        t.id === tableId
          ? { ...t, status: "disponible", guests: undefined, time: undefined, total: undefined }
          : t
      )
    );
  }
  setSelectedTable(null);
};

FLUJO COMPLETO DE ÓRDENES EN MANGOPOS
1. PUNTO DE ENTRADA: PÁGINA DE VENTAS
La página principal de ventas (/ventas) está compuesta por:

VentasSidebar: Barra lateral izquierda con opciones de navegación (Por zona, Venta manual, Venta rápida, Delivery, Self service). Actualmente solo es visual, no tiene funcionalidad implementada.
TablesGrid: Grilla principal de mesas que muestra las mesas organizadas por zonas (Salón Principal, Terraza, VIP).
2. DATOS DE MESAS
Las mesas están definidas como un array estático (initialTables) en TablesGrid.tsx con la siguiente estructura:


{
  id: string,           // Identificador único
  code: string,         // Código visual (SP01, TR01, VIP01)
  status: "disponible" | "ocupado" | "pagando",
  guests?: number,      // Número de comensales
  time?: string,        // Tiempo transcurrido
  total?: number,       // Total acumulado
  zone: string          // Zona: "salon", "terraza", "vip"
}
Las mesas se filtran dinámicamente según la zona activa (tabs en la parte superior).

3. SELECCIÓN DE MESA
Cuando el usuario hace clic en una mesa (handleTableClick):

Se guarda la mesa seleccionada en el estado selectedTable
Se renderiza condicionalmente el componente OrderScreen en lugar de la grilla de mesas
Se pasa la información de la mesa al OrderScreen
4. PANTALLA DE ORDEN (OrderScreen)
Este es el componente central del flujo. Layout de dos columnas:

Columna izquierda (380px fijos) - Componente Cart:

Encabezado con nombre de mesa o "Venta Rápida"
Lista de productos agregados con:
Nombre del producto
Modificadores seleccionados (con precio adicional si aplica)
Notas especiales
Controles de cantidad (+/-)
Precio total del ítem
Botón para eliminar
Resumen financiero:
Subtotal
ITBIS (18%)
Total
Botones de acción:
Enviar a Cocina (solo si es venta por mesa y no se ha enviado aún)
Dividir Cuenta (solo si es venta por mesa y ya se envió a cocina)
Pagar (siempre visible)
Columna derecha - Componente ProductCatalog:

Barra de búsqueda
Tabs: Categorías, Menú, Favoritos
Vista de categorías (si no hay categoría seleccionada)
Vista de productos (al seleccionar una categoría o buscar)
Cada producto muestra:
Nombre
Precio
Badge "Con modificadores" si tiene modificadores
5. HOOK useCart - GESTIÓN DEL CARRITO
El hook useCart maneja todo el estado del carrito:

Estado:

items: Array de CartItem[]
Funciones:

addItem(product, quantity, modifiers, notes): Agrega un producto con sus modificadores y notas
updateItemQuantity(itemId, quantity): Actualiza la cantidad. Si llega a 0, elimina el ítem
removeItem(itemId): Elimina un ítem específico
clearCart(): Vacía el carrito
setItems(items): Reemplaza todos los ítems
Cálculos derivados (useMemo):

subtotal: Suma de todos los totalPrice de los ítems
tax: subtotal * 0.18 (ITBIS 18%)
total: subtotal + tax
itemCount: Suma de todas las cantidades
Estructura de CartItem:


{
  id: string,                    // ID único generado aleatoriamente
  productId: string,             // ID del producto original
  product: Product,              // Referencia al producto
  quantity: number,              // Cantidad
  selectedModifiers: SelectedModifier[],
  notes: string,                 // Notas especiales
  unitPrice: number,             // Precio base + modificadores
  totalPrice: number             // unitPrice * quantity
}
6. SELECCIÓN DE PRODUCTO
Cuando el usuario hace clic en un producto:

Si el producto NO tiene modificadores (hasModifiers: false):

Se agrega directamente al carrito con cantidad 1, sin modificadores, sin notas
Se muestra toast de confirmación
Si el producto TIENE modificadores (hasModifiers: true):

Se abre el modal ProductCustomizationModal
7. MODAL DE PERSONALIZACIÓN (ProductCustomizationModal)
Estado interno:

quantity: Cantidad (inicia en 1)
selectedModifiers: Map<groupId, Set<modifierId>>
notes: Notas especiales
Funcionalidades:

Control de cantidad (+/-)
Grupos de modificadores con reglas:
required: Si es obligatorio seleccionar
minSelection/maxSelection: Límites de selección
Si maxSelection === 1: Usa RadioGroup (selección única)
Si maxSelection > 1: Usa Checkboxes (selección múltiple)
Notas rápidas predefinidas: "Sin azúcar", "Con azúcar", "Sin sal", etc.
Campo de texto libre para notas adicionales
Cálculo de precio dinámico:


modifiersTotal = suma de precios de modificadores seleccionados
unitPrice = product.price + modifiersTotal
totalPrice = unitPrice * quantity
Validación:

Verifica que todos los grupos required tengan la selección mínima requerida
El botón "Agregar al pedido" se deshabilita si no es válido
Al confirmar:

Se llama a cart.addItem() con todos los datos
Se cierra el modal y se resetea el estado
8. ENVÍO A COCINA
Al presionar "Enviar a Cocina":

Se cambia el estado orderSent a true
Se muestra un toast de confirmación
El botón "Enviar a Cocina" se oculta
Se habilita el botón "Dividir Cuenta"
NOTA IMPORTANTE: Actualmente NO hay integración real con cocina. Es solo un cambio de estado visual local.

9. DIVISIÓN DE CUENTA (SplitBillModal)
Estado interno:

subAccounts: Array de subcuentas creadas
selectedItems: Set de IDs de ítems seleccionados
equalSplitCount: Número de personas para división igualitaria
Flujo manual:

Crear subcuenta con botón "Nueva"
Seleccionar productos de la lista izquierda (checkbox)
Asignar a una subcuenta con los botones que aparecen
Los productos asignados desaparecen de la lista izquierda
Cada subcuenta calcula su propio subtotal, tax y total
Flujo división igualitaria:

Clic en "Partes iguales"
Ingresar número de personas
Se crean N subcuentas automáticamente
El total se divide entre todas (con ajuste de centavos en la primera)
Al confirmar:

Se guardan las subcuentas en el estado del OrderScreen
Se muestra toast de confirmación
NOTA: Actualmente las subcuentas se guardan pero NO se usan para el pago. El pago sigue siendo del total completo.

10. PAGO (PaymentModal)
Métodos de pago:

Efectivo (con teclado numérico)
Tarjeta
Transferencia
Para efectivo:

Montos rápidos: RD$ 100, 200, 500, 1000, 2000, 5000
Botón "Monto exacto"
Teclado numérico para ingresar monto
Cálculo de cambio automático
Solo se puede confirmar si el monto recibido >= total
Para tarjeta/transferencia:

No requiere monto, se asume el total
Al confirmar:

Se llama a onConfirmPayment(method, amount)
Se muestra toast con el cambio (si aplica)
Se llama a onOrderComplete(tableId) que:
Actualiza la mesa a status "disponible"
Limpia guests, time, total
Cierra el OrderScreen
Vuelve a la grilla de mesas
11. VENTA RÁPIDA
Actualmente definida en el OrderScreen con isQuickSale={true}:

Mismo flujo pero sin mesa asociada
Sin botón "Enviar a Cocina"
Sin opción de "Dividir Cuenta"
El carrito muestra "Venta Rápida" en lugar del código de mesa
NOTA: El sidebar de VentasSidebar tiene el botón "Venta rápida" pero NO está conectado funcionalmente. Solo el flujo desde mesas está implementado.

LIMITACIONES ACTUALES
Sin persistencia: Todo es estado local en React. Al refrescar se pierde.
Sin integración con cocina real: "Enviar a cocina" solo cambia un estado visual.
Venta rápida no accesible: El sidebar no tiene handlers implementados.
División de cuenta incompleta: Se crean subcuentas pero el pago no las considera.
Sin clientes: El botón "Asignar cliente" no hace nada.
Sin comprobantes fiscales: No hay generación de NCF ni facturación.
Mesas estáticas: Las mesas son datos mock, no vienen de base de datos.
Sin timer real: Los tiempos de las mesas ocupadas son estáticos.
¿Te gustaría que prepare un plan para implementar alguna mejora específica, como la persistencia de datos, la integración real del flujo de venta rápida, o la conexión con base de datos?

Funcion auxiliar para verificar membresia:


CREATE OR REPLACE FUNCTION public.user_has_business_access(
  _user_id uuid, 
  _business_id uuid
)
RETURNS boolean
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT EXISTS (
    SELECT 1 FROM public.user_businesses
    WHERE user_id = _user_id 
    AND business_id = _business_id
  ) OR EXISTS (
    SELECT 1 FROM public.businesses
    WHERE id = _business_id 
    AND owner_id = _user_id
  )
$$;
Funcion para verificar rol:


CREATE OR REPLACE FUNCTION public.user_business_role(
  _user_id uuid, 
  _business_id uuid
)
RETURNS text
LANGUAGE sql
STABLE
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT COALESCE(
    (SELECT role FROM public.user_businesses 
     WHERE user_id = _user_id AND business_id = _business_id),
    (SELECT 'owner' FROM public.businesses 
     WHERE id = _business_id AND owner_id = _user_id)
  )
$$;

Fase 7: Datos Iniciales por Defecto
7.1 Funcion para crear datos iniciales de negocio:


CREATE OR REPLACE FUNCTION public.create_business_defaults(_business_id uuid)
RETURNS void
LANGUAGE plpgsql
AS $$
BEGIN
  -- Metodos de pago por defecto
  INSERT INTO public.payment_methods (business_id, name, code, position, icon) VALUES
    (_business_id, 'Efectivo', 'cash', 1, 'banknote'),
    (_business_id, 'Tarjeta', 'card', 2, 'credit-card'),
    (_business_id, 'Transferencia', 'transfer', 3, 'building-2');
  
  -- Moneda por defecto (Peso Dominicano)
  INSERT INTO public.currencies (business_id, code, name, symbol, is_default) VALUES
    (_business_id, 'DOP', 'Peso Dominicano', 'RD$', true);
  
  -- Configuracion por defecto
  INSERT INTO public.business_settings (business_id) VALUES (_business_id);
  
  -- Impuesto ITBIS por defecto
  INSERT INTO public.taxes (business_id, name, rate) VALUES
    (_business_id, 'ITBIS', 18);
  
  -- Zona por defecto
  INSERT INTO public.zones (business_id, name, sort_index) VALUES
    (_business_id, 'Salon Principal', 1);
  
  -- Almacen principal
  INSERT INTO public.warehouses (business_id, name, is_main) VALUES
    (_business_id, 'Almacen Principal', true);
END;
$$;
7.2 Trigger para crear datos al crear negocio:


CREATE OR REPLACE FUNCTION public.trigger_create_business_defaults()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  PERFORM public.create_business_defaults(NEW.id);
  
  -- Agregar owner a user_businesses
  INSERT INTO public.user_businesses (user_id, business_id, role)
  VALUES (NEW.owner_id, NEW.id, 'owner');
  
  RETURN NEW;
END;
$$;

CREATE TRIGGER create_business_defaults
AFTER INSERT ON public.businesses
FOR EACH ROW
EXECUTE FUNCTION public.trigger_create_business_defaults();
